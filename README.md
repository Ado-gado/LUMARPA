# Account Registration Automation

Серверное Node.js-приложение для автоматизации регистрации аккаунтов.

## Описание

Система выполняет полный цикл регистрации на целевом сайте:
1. Выбирает свободный email и прокси из базы данных SQLite
2. Создаёт изолированный браузерный профиль в AdsPower с привязанным прокси
3. Автоматически заполняет форму регистрации через Playwright
4. Решает капчи через Capsolver
5. Получает код подтверждения через firstmail.ltd IMAP API
6. Сохраняет cookies и фиксирует результат в базе данных

## Стек

- **Node.js** >= 18
- **Playwright** — автоматизация браузера через CDP
- **AdsPower Local API** — управление браузерными профилями
- **better-sqlite3** — база данных SQLite (синхронный API)
- **Capsolver** — решение капч
- **firstmail.ltd** — получение кодов подтверждения по IMAP API
- **winston** — логирование с ротацией файлов

## Установка

```bash
npm install
```

## Конфигурация

Скопируйте шаблон конфигурации и заполните значения:

```bash
cp config/.env.example .env
```

Обязательные параметры в `.env`:
- `TARGET_URL` — URL целевого сайта регистрации
- `ADSPOWER_API_URL` — URL AdsPower Local API (обычно `http://local.adspower.net:50325`)
- `ADSPOWER_GROUP_ID` — ID группы профилей в AdsPower
- `CAPSOLVER_API_KEY` — API-ключ Capsolver
- `FIRSTMAIL_TOKEN` — токен авторизации firstmail.ltd
- `DB_PATH` — путь к файлу SQLite (например, `./data.db`)

## Запуск

```bash
node src/index.js
```

## Структура проекта

```
├── src/
│   ├── database/       # Модуль базы данных (SQLite/PostgreSQL)
│   ├── services/       # Сервисы: AdsPower, Email, Captcha, Cookies
│   ├── config.js       # Загрузка и валидация конфигурации
│   ├── logger.js       # Модуль логирования (winston)
│   ├── worker.js       # Оркестратор одного цикла регистрации
│   └── index.js        # Точка входа, параллельный запуск воркеров
├── config/
│   └── .env.example    # Шаблон конфигурации
├── logs/               # Файлы логов (создаётся автоматически)
├── screenshots/        # Скриншоты ошибок (создаётся автоматически)
├── cookies/            # Сохранённые cookies (создаётся автоматически)
├── .env                # Конфигурация (не в git)
└── package.json
```

## Логирование

Логи пишутся в `stdout` и в файлы в директории `logs/` с ротацией по дате.
Уровень логирования задаётся параметром `LOG_LEVEL` (по умолчанию `info`).

## Обработка ошибок

При ошибке на любом шаге:
- Делается скриншот и сохраняется в `screenshots/`
- Ошибка записывается в таблицу `error_logs` в БД
- Email возвращается в очередь (если не превышен `MAX_RETRIES`)
- Браузерный профиль останавливается
